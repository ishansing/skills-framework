## Threat assessment and ownership

Remote contributors control PR text, branch names, diffs and misleading metadata; they
do not confer publication grants. Full host/base/head repositories, refs and expected
SHAs bind the prepared/current context. Current passed review/verification and a separate
create/update/status grant precede writes. Existing `pr` remains the sole body formatter;
file-pr is a user entry, not a new automatic adapter child or alternate verification gate.

Existing PR lookup/update requires full target identity and exact-field/content authority;
a same-named fork branch is not a match. Draft status, secret/private content, verified
human credit and public model/harness attribution are checked before publication. These
are agent-followed instructions, not deterministic validators or authenticated identities.

Uncertain write responses reconcile through reads without blind retry. REST fallback
requires separate authority, definite pre-write rejection and unambiguous target-state
reconciliation. Wrong/missing receipt or drift keeps actual known write outcome separate
from verification and completion. No implicit Git push, comments, resolution, settings,
monitoring, merge, closure or user-entry recursion is introduced.

The head/base/content read/write window is not atomic. Creation tracks a live branch,
and PR body replacement has no claimed atomic CAS. No exactly-once or live consistency
guarantee follows from fake-service state, host permissions or prose guardrails.

History/blame retains `ed7c6eb` formatting/user-handoff boundaries, `c5b1266` separate
comment grants, `a2fc0ad` monitoring vs verification, and `26efe98` fresh review/verify
before separately granted delivery. Static blast radius: zero automatic production
file-pr invocations; one itp-verify user handoff and one lifecycle reference, reached
